第 2 页
一、共同的数据背景与符号
以一个 RGB-D 跟踪样本为例，R 表示 RGB，X 表示深度模态。RGB-T 和 RGB-E 的处
理方式相同，只需把 X 换成热红外或事件模态。一个样本同时包含模板区域和搜索区域。
默认模板为 128×128，搜索区域为 256×256，patch 大小为 16×16。因此每个模态包含
64 个模板 token 和 256 个搜索 token，每个 token 有 768 个特征值。
每个模态：
[64 个模板 token；256 个搜索 token] = 320 个 token
形状 = [B, 320, 768]
本例中 B = 1
B 是批大小，N 是当前模块输入的 token 数，D 是每个 token 的特征维度。H_R 和 H_X
表示经过 LayerNorm 的两路特征矩阵，并不是图像高度。h_i 表示第 i 个 token 的行向量。
注意力头数用 n_head 表示，默认是 12；每头维度 d_head = 768/12 = 64。HMoE 中的
S=2 表示通道分组数，同时对应每个专家的槽位数，与注意力头数不同。
在启用这些模块的 Transformer block 中，主要顺序为：LayerNorm、AMG-LoRA 注意力、
注意力残差、HMoE 融合残差、LayerNorm 与 MLP 残差、第二个 HMoE 融合残差。经
过全部 blocks 后，骨干输出搜索特征，再送入预测头。

第 3 页
二、AMG-LoRA：注意力关系引导与低秩适配
2.1 源码中哪些是作者定义的？
CEBlock_AP.cal_qkv、CEBlock_AP.amglora_attn 和 MergedLinear 都是项目源码中定
义的函数或类，不是 PyTorch 自带的同名接口。它们内部使用 nn.Linear、LayerNorm、
softmax、矩阵乘法、reshape 和 transpose 等库操作。LayerNorm 用于规范化单个
token 的特征，reshape/transpose 负责整理维度，softmax 把分数转换成权重。
2.2 第一步：由 token 计算 Q、K、V
令输入特征经过 LayerNorm 后得到 H。Q 表示当前位置用于查询的特征，K 表示其他位
置供匹配的特征，V 表示最终要取回并混合的信息。当前增强层只对 K 和 V 添加 LoRA
，Q 不添加 LoRA。
Q = H W_Q + b_Q
K = H W_K + b_K + H A_K B_K
V = H W_V + b_V + H A_V B_V
H: [B, 320, 768]
A_K, A_V: [768, 8]
B_K, B_V: [8, 768]
A 先把 768 维映射到 8 维，B 再映射回 768 维，因此 A B 构成一个秩至多为 8 的更新矩
阵。单个 K 或 V 的低秩矩阵共有 768×8+8×768=12,288 个参数。这里是在原投影上加一
个可训练修正。源码将 LoRA 的 B 矩阵初始化为零，所以初始修正为零；虽然定义了
alpha/r，当前实际计算中对应乘法被注释掉，不能额外套用这个缩放。
代码先一次性生成 [B,320,2304]，再拆成 Q、K、V 和 12 个头。最终每个 Q/K/V 的形状
为 [B,12,320,64]。同一层的两种模态使用同一套投影参数，但输入不同，因此得到的
Q/K/V 不同。

2.3 第二步：分别计算两种模态的注意力分数
S_R = Q_R K_R^T / sqrt(d_head)
S_X = Q_X K_X^T / sqrt(d_head)
d_head = 64，因此 sqrt(d_head) = 8
S_R, S_X: [B, 12, 320, 320]
第 i 行、第 j 列表示“第 i 个 token 对第 j 个 token 的匹配分数”。这些还是 softmax 之前的
logits，不是概率。cal_qkv 返回的是这个分数矩阵和 V，并不是直接把 Q、K、V 三个张
量返回。
2.4 第三步：用另一模态的关系修正本模态的关系
S_R_new = S_R + alpha (S_X - S_R)
S_X_new = S_X + beta  (S_R - S_X)
alpha = self.dte2r_scaling
beta  = self.r2dte_scaling
alpha 表示 X 引导 RGB 的强度，beta 表示 RGB 引导 X 的强度。它们是每个增强层中可
训练的标量，初始化为 1，源码没有用 sigmoid 限制其范围。只有当系数在 [0,1] 内时，
才能解释为两种分数的凸组合。两条更新都使用原始 S_R 和 S_X，不会把第一条已经修
改的分数再送给第二条。
这里交换的是“位置之间的关系”。RGB 分支仍使用自己的 V_R，X 分支仍使用自己的
V_X。因此其计算不是直接用 Q_R K_X^T 做跨模态注意力。
2.5 第四步：取回信息并加残差
P_R = softmax(S_R_new, 沿 key 位置维度)
P_X = softmax(S_X_new, 沿 key 位置维度)
O_R = ConcatHeads(P_R V_R) W_O + b_O
O_X = ConcatHeads(P_X V_X) W_O + b_O

三、HMoE：先汇聚到专家，再分配回 token
3.1 来源与功能
HMoE、LoRP 和 MultiExpertLinear 都是项目源码中的自定义类。HMoE 接收两种模态的
token，用可学习的路由权重将信息汇聚给多个专家，再把专家输出分配给每个 token。
内部的 LayerNorm、softmax、矩阵乘法和 reshape 是基础库操作。
3.2 第一步：Divide & Concat
先把每个模态的 320 个 token 分成模板和搜索两段。两种模态的模板相拼，两种模态的
搜索相拼。这里沿 token 维拼接，不是把两个 768 维向量拼成 1536 维。
Z_mix = ConcatTokens(Z_R, Z_X): [B, 128, 768]
S_mix = ConcatTokens(S_R_features, S_X_features): [B, 512, 768]
模板与搜索分别调用同一个 HMoE，因此共享该模块的参数，但不在同一次 HMoE 路由
中混在一起。注意力后的 HMoE 有 4 个专家，MLP 后的 HMoE 有 8 个专家，两者是独
立模块。下面以注意力后的搜索融合为例，取 N=512、D=768、E=4、S=2、低秩 r=4。
3.3 第二步：低秩投影与通道拆分
Z = LoRP_1(LayerNorm(X_mix))
LoRP(u) = (u A + a) B + b     [推理状态，默认激活设置]
U = reshape(Z, [B, N×S, D/S])
[B,512,768] → [B,512,768] → [B,1024,384]
LoRP 默认执行 768→4→768 的带偏置映射，默认没有 GELU，训练时包含 dropout。它
是一个独立的低秩投影，不是把低秩更新加到另一个冻结大矩阵上的 LoRA。随后将每个
768 维 token 按通道拆成两个 384 维子 token。拆分顺序是 token0 的两份、token1 的
两份，依次排列；这一步没有重新切割图像。

3.4 第三步：计算路由分数和 Dispatch
Phi = gate_thi: [D/S, E×S] = [384,8]
L = U Phi: [B,1024,8]
Dispatch[i,j] = exp(L[i,j]/T_D) / sum_k exp(L[k,j]/T_D)
Phi 的每一列对应一个专家槽位。4 个专家、每个专家 2 个槽位，总共 8 个槽位。L[i,j] 表
示第 i 个输入子 token 对第 j 个槽位的路由分数。Dispatch 对所有输入子 token 做归一化
，因此每一列之和为 1，表示一个槽位如何从全部输入收集信息。
G = Dispatch^T U
[B,8,1024] @ [B,1024,384] = [B,8,384]
reshape G → [B,4,2,384]
每个槽位得到一个 384 维加权和，其中已经可能包含 RGB、X 以及不同空间位置的信息。
这里所有专家都参与运算，不是仅选择 top-k 专家的稀疏路由。
3.5 第四步：专家计算和第二次低秩投影
Expert_e(g) = (g A_e + a_e) B_e + b_e
A_e: [384,4], B_e: [4,384]
F_e = LoRP_2(ConcatChannels(Expert_e(G_e,1), Expert_e(G_e,2)))
[B,4,2,384] → [B,4,768] → [B,4,768]
不同专家使用不同参数，但同一个专家的两个槽位共享该专家的参数。每个槽位经过
384→4→384 的变换后，将同一专家的两个结果拼回 768 维，再经过共享的 linear2，即
768→4→768 的 LoRP。不能漏掉源码中的这次 linear2。
3.6 第五步：Combine 与 token 输出
Combine 使用原始路由分数 L 的另一条计算分支。把 L 看成 [B,N,S,E,S]，将一个 token
的两个通道分组和一个专家的两个槽位所对应的分数全部相加，得到 [B,N,E]。随后沿专
家维做 softmax。

第 9 页
M[n,e] = sum_a sum_b L[n×S+a, e×S+b]
Combine[n,e] = softmax_e(M[n,e]/T_C)
Y[n] = sum_e Combine[n,e] F_e
[B,512,4] @ [B,4,768] = [B,512,768]
Dispatch 回答“每个专家槽位从哪里收集信息”，Combine 回答“每个 token 从哪些专家取
回多少信息”。Combine 不是对 Dispatch 再做一次 softmax。T_D 和 T_C 是可学习温度
，初始化为 1，当前代码没有对其施加正值约束。
最后把输出重新拆成 RGB 和 X，分别取回模板与搜索片段，恢复每个模态的
[B,320,768] 形状，再加到对应原特征上。这一残差在 CEBlock_AP 中完成，而不是
HMoE.forward 内部完成。

第 12 页
四、预测头：把搜索特征变成目标框
4.1 来源与输入
CenterPredictor、get_score_map、cal_bbox 和模型的 forward_head 是项目中定义的结
构或函数。内部使用 PyTorch 的 Conv2d、BatchNorm2d、ReLU、sigmoid、max 和
gather。卷积提取局部特征，BatchNorm 规范化中间激活，ReLU 提供非线性，gather
按选定索引取值。下面重点解释三个输出分支如何一起完成框预测。
全部 Transformer blocks 处理结束后，两路特征经过最后的归一化，并取搜索部分。
RGB 和 X 的搜索特征逐位置、逐通道相加，得到 [B,256,768]。这是求和，不是通道拼
接。
F_search = F_R_search + F_X_search
[B,256,768] → [B,768,16,16]
256 个搜索 token 对应 16×16 个空间位置，因此可以恢复成二维特征图。每个位置有
768 个通道。模板特征没有单独送进预测头，但已经在前面的注意力计算中影响了搜索特
征。
4.2 三个独立分支
中心分数、尺寸和偏移三个分支具有相同的层次结构，但各用各的卷积参数。每支先经
过四层 3×3 的 Conv-BN-ReLU，通道数为 768→256→128→64→32，空间大小保持 16×16。
最后一层 1×1 卷积输出所需的通道数。
中心分数：
  score_map: [B,1,16,16]
  含义：每个网格位置作为目标中心的分数
尺寸：
  size_map: [B,2,16,16]
  含义：每个位置预测的归一化宽度和高度

  offset_map: [B,2,16,16]
  含义：相对网格坐标的 x、y 方向修正量
中心分数和尺寸经过 sigmoid，并限制在 [0.0001,0.9999]。偏移不经过 sigmoid，可以取
任意实数。中心分数是在每个位置独立计算的，并不是对 256 个位置做一次 softmax，
因此整张中心分数图的分数和不要求为 1。
4.3 选择位置，并在同一位置取出尺寸与偏移
idx = argmax(flatten(score_map))
row = idx // 16
col = idx % 16
[w,h]   = size_map 在 idx 位置的值
[dx,dy] = offset_map 在 idx 位置的值
先在中心分数图找到最大分数位置，再从尺寸图和偏移图的同一个位置取值。不能让三
个分支分别选各自的最大值，否则中心、宽高和偏移可能来自三个不同位置。
4.4 解码归一化目标框
cx = (col + dx) / 16
cy = (row + dy) / 16
box = [cx, cy, w, h]
cx、cy 是相对搜索图的归一化中心坐标。w、h 已经是相对搜索图的归一化宽高，因此不
要再除以 16。此时输出是中心形式 cxcywh，不是左上角形式 xywh，也不是原图像素坐
标。

五、三个模块如何衔接
AMG-LoRA 在注意力计算中调整 K/V 投影，并利用另一模态的注意力关系修正本模态的
取信息方式。HMoE 接收注意力或 MLP 更新后的 token，将两种模态的信息汇聚到专家
，再按每个 token 的权重返回融合增量。预测头接收最终搜索特征，生成中心、尺寸和
偏移图，再将它们解码成目标框。
AMG-LoRA 和 HMoE 位于 Transformer blocks 的特征处理过程中；预测头位于编码器之
后。HMoE 的输出仍然是 token 特征，预测头才将这些特征转换成可用于跟踪的目标位
置与大小。
