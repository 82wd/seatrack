Reading notes
This document follows the current project source code. It explains the mathematics of
project-defined modules and computation flows, while briefly describing the roles of basic
PyTorch and timm operations. All hand-calculated values are illustrative examples, not
predictions from an actual checkpoint or evaluation results from the paper. Equations use
row vectors multiplied by weight matrices. PyTorch Linear usually stores weights as
[out_features, in_features], so its implementation may use a transpose relative to this
notation.

1. Shared data setup and notation
Consider one RGB-D tracking sample, with R denoting RGB and X denoting depth. RGB-T
and RGB-E follow the same structure, with thermal or event data as X. Each sample
contains a template region and a search region. The default template is 128×128, the
search region is 256×256, and each patch is 16×16. Each modality therefore contains 64
template tokens and 256 search tokens, with 768 features per token.
Each modality:
[64 template tokens; 256 search tokens] = 320 tokens
Shape = [B, 320, 768]
B = 1 in this example
B is the batch size, N is the number of tokens entering the current module, and D is the
feature dimension per token. H_R and H_X denote the feature matrices after LayerNorm,
not image height. h_i denotes the row vector of token i. The attention head count is
n_head=12, giving d_head=768/12=64. In HMoE, S=2 denotes the channel split count and
also the number of slots per expert. It is distinct from the attention head count.
In a Transformer block that enables these modules, the main sequence is LayerNorm,
AMG-LoRA attention, the attention residual, an HMoE fusion residual, a LayerNorm/MLP
residual, and a second HMoE fusion residual. After all blocks, the backbone outputs search
features for the prediction head.

2. AMG-LoRA: attention guidance and low-rank
adaptation
2.1 Which parts are defined in the project?
CEBlock_AP.cal_qkv, CEBlock_AP.amglora_attn and MergedLinear are functions or
classes defined in the project, not built-in PyTorch interfaces with those names. They use
library operations such as nn.Linear, LayerNorm, softmax, matrix multiplication, reshape
and transpose. LayerNorm normalizes each token's features, reshape/transpose organize
dimensions, and softmax converts scores into weights.
2.2 Step 1: compute Q, K and V from tokens
Let H be the features after LayerNorm. Q provides query features for the current position, K
provides features for matching other positions, and V carries the information to retrieve and
mix. In the enhanced layers, LoRA modifies K and V only. Q has no LoRA update.
Q = H W_Q + b_Q
K = H W_K + b_K + H A_K B_K
V = H W_V + b_V + H A_V B_V
H: [B, 320, 768]
A_K, A_V: [768, 8]
B_K, B_V: [8, 768]
A maps 768 features down to 8, and B maps them back to 768. Their product A B is an
update matrix of rank at most 8. The low-rank matrices for either K or V contain
768×8+8×768=12,288 parameters. This adds a trainable correction to the original
projection. The code initializes the LoRA B matrix to zero, so the initial correction is zero.
Although alpha/r is defined, its multiplication is commented out in the current computation
and must not be inserted into the equations.
The code first produces [B,320,2304], then separates Q, K and V and divides them into 12
heads. Each resulting tensor has shape [B,12,320,64]. Both modalities use the same
projection parameters within a layer, but their different inputs produce different Q/K/V
tensors.

2.3 Step 2: compute attention scores for each modality
S_R = Q_R K_R^T / sqrt(d_head)
S_X = Q_X K_X^T / sqrt(d_head)
d_head = 64, so sqrt(d_head) = 8
S_R, S_X: [B, 12, 320, 320]
Entry (i,j) is the matching score between query token i and key token j. These are logits
before softmax, not probabilities. Despite its name, cal_qkv returns this score matrix and V,
rather than returning Q, K and V separately.
2.4 Step 3: use the other modality to guide attention relations
S_R_new = S_R + alpha (S_X - S_R)
S_X_new = S_X + beta  (S_R - S_X)
alpha = self.dte2r_scaling
beta  = self.r2dte_scaling
alpha controls guidance from X to RGB, while beta controls guidance from RGB to X. They
are trainable scalars in each enhanced layer, initialized to 1, with no sigmoid constraint. The
update is a convex combination only when the coefficient lies in [0,1]. Both directions use
the original S_R and S_X. The second update does not use the already modified score
matrix from the first update.
The guidance exchanges relations between positions. The RGB branch still uses its own
V_R, and the X branch still uses its own V_X. It does not directly compute cross-modal
attention as Q_R K_X^T.
2.5 Step 4: retrieve information and add the residual
P_R = softmax(S_R_new, along key positions)
P_X = softmax(S_X_new, along key positions)
O_R = ConcatHeads(P_R V_R) W_O + b_O
O_X = ConcatHeads(P_X V_X) W_O + b_O

X_R_after = X_R_before + O_R
X_X_after = X_X_before + O_X
Each softmax row sums to 1. Subsequent dropout during training can change that sum,
while dropout is disabled during inference. P V forms weighted sums of token values.
Concatenating the heads restores [B,320,768], followed by an output projection. The
residual adds the original input from before LayerNorm, not the normalized H. The variables
xrgb_attn and xdte_attn contain feature updates, not 320×320 attention maps.

Set alpha=0.75. The first RGB token's score row becomes [1.4142,1.0607], producing

O_R_first = 0.5875 × [1,0] + 0.4125 × [0,2]

O_X_first = 0.6698 × [1,0] + 0.3302 × [1,2]

3. HMoE: aggregate into experts, then distribute
back to tokens
3.1 Implementation and purpose
HMoE, LoRP and MultiExpertLinear are custom classes in the project. HMoE receives
tokens from both modalities, uses learned routing weights to aggregate information into
multiple experts, and distributes the expert outputs back to each token. LayerNorm,
softmax, matrix multiplication and reshape are underlying library operations.
3.2 Step 1: Divide & Concat
First split each modality's 320 tokens into template and search segments. Concatenate the
two modalities' template segments together, and concatenate their search segments
together. Concatenation is along the token dimension, not along the feature dimension to
create 1536-dimensional vectors.
Z_mix = ConcatTokens(Z_R, Z_X): [B, 128, 768]
S_mix = ConcatTokens(S_R_features, S_X_features): [B, 512, 768]
Template and search tokens call the same HMoE module separately, sharing its parameters
without mixing in a single routing operation. The HMoE after attention has 4 experts, while
the HMoE after the MLP has 8 experts. They are independent modules. The following
example uses search fusion after attention, with N=512, D=768, E=4, S=2 and low rank r=4.
3.3 Step 2: low-rank projection and channel splitting
Z = LoRP_1(LayerNorm(X_mix))
LoRP(u) = (u A + a) B + b     [inference, default activation]
U = reshape(Z, [B, N×S, D/S])
[B,512,768] → [B,512,768] → [B,1024,384]
LoRP performs a biased 768→4→768 mapping, with no GELU by default and with dropout
during training. It is an independent low-rank projection, rather than a LoRA update added
to another frozen full-sized matrix. Each 768-dimensional token is then split into two

384-dimensional subtokens along its channels. The order is the two parts of token 0,
followed by the two parts of token 1, and so on. This operation does not cut the image into
new patches.
3.4 Step 3: compute routing scores and Dispatch
Phi = gate_thi: [D/S, E×S] = [384,8]
L = U Phi: [B,1024,8]
Dispatch[i,j] = exp(L[i,j]/T_D) / sum_k exp(L[k,j]/T_D)
Each column of Phi corresponds to an expert slot. With 4 experts and 2 slots per expert,
there are 8 slots. L[i,j] is the routing score from input subtoken i to slot j. Dispatch
normalizes across input subtokens, so each column sums to 1 and determines how one slot
collects information from all inputs.
G = Dispatch^T U
[B,8,1024] @ [B,1024,384] = [B,8,384]
reshape G → [B,4,2,384]
Each slot receives a 384-dimensional weighted sum that can contain information from RGB,
X and different spatial locations. All experts participate. This is not sparse routing that
selects only the top-k experts.
3.5 Step 4: expert computation and the second low-rank projection
Expert_e(g) = (g A_e + a_e) B_e + b_e
A_e: [384,4], B_e: [4,384]
F_e = LoRP_2(ConcatChannels(Expert_e(G_e,1), Expert_e(G_e,2)))
[B,4,2,384] → [B,4,768] → [B,4,768]
Different experts use different parameters, while the two slots within one expert share that
expert's parameters. After each slot undergoes a 384→4→384 transform, the two outputs
from the same expert are concatenated back to 768 features. The shared linear2 then

applies another 768→4→768 LoRP. This additional linear2 operation is part of the
implementation and must be included.
3.6 Step 5: Combine and token outputs
Combine is another computation branch based on the original routing scores L. View L as
[B,N,S,E,S]. Sum the scores over the two channel groups of each token and the two slots of
each expert to obtain [B,N,E], then apply softmax across experts.
M[n,e] = sum_a sum_b L[n×S+a, e×S+b]
Combine[n,e] = softmax_e(M[n,e]/T_C)
Y[n] = sum_e Combine[n,e] F_e
[B,512,4] @ [B,4,768] = [B,512,768]
Dispatch determines where each expert slot collects information. Combine determines how
much information each token retrieves from each expert. Combine is not a second softmax
applied to Dispatch. T_D and T_C are learnable temperatures initialized to 1, with no
positivity constraint in the current code.
Finally, split the outputs back into RGB and X, reunite each modality's template and search
segments to restore [B,320,768], and add them to the corresponding input features.
CEBlock_AP performs this residual addition, not HMoE.forward itself.

4. Prediction head: convert search features into
a bounding box
4.1 Implementation and input
CenterPredictor, get_score_map, cal_bbox and the model's forward_head are structures or
functions defined in the project. They use PyTorch Conv2d, BatchNorm2d, ReLU, sigmoid,
max and gather. Convolutions extract local features, BatchNorm normalizes intermediate
activations, ReLU supplies nonlinearity, and gather retrieves values at selected indices. The
explanation below focuses on how the three output branches jointly predict a box.
After all Transformer blocks, both streams undergo final normalization, and the search
features are selected. The RGB and X search features are added element by element,
producing [B,256,768]. This is addition, not channel concatenation.
F_search = F_R_search + F_X_search
[B,256,768] → [B,768,16,16]
The 256 search tokens correspond to a 16×16 spatial grid, so they can be reshaped into a
two-dimensional feature map with 768 channels per location. Template features are not
separately passed to the prediction head, but they have already influenced the search
features through earlier attention operations.
4.2 Three independent branches
The center-score, size and offset branches have the same layer structure but use separate
convolution parameters. Each branch applies four 3×3 Conv-BN-ReLU layers with channels
768→256→128→64→32, keeping the spatial grid at 16×16. A final 1×1 convolution
produces the required output channels.
Center score:
  score_map: [B,1,16,16]
  Meaning: target-center score at each grid position

Size:
  size_map: [B,2,16,16]
  Meaning: normalized width and height at each position
Offset:
  offset_map: [B,2,16,16]
  Meaning: x and y corrections relative to each grid coordinate
Center scores and sizes pass through sigmoid and are clamped to [0.0001,0.9999]. Offsets
have no sigmoid and can take arbitrary real values. Center scores are computed
independently at each location, rather than using a single softmax over all 256 locations, so
the entire score map need not sum to 1.
4.3 Select a location and retrieve its size and offset
idx = argmax(flatten(score_map))
row = idx // 16
col = idx % 16
[w,h]   = size_map at idx
[dx,dy] = offset_map at idx
First find the location with the highest center score, then retrieve size and offset from that
same location. The three branches must not independently select their own maxima,
because that could combine a center, size and offset from different positions.
4.4 Decode the normalized bounding box
cx = (col + dx) / 16
cy = (row + dy) / 16
box = [cx, cy, w, h]
cx and cy are center coordinates normalized relative to the search image. w and h are
already normalized to the search image, so they must not be divided by 16 again. The
output is in center-based cxcywh form, not top-left xywh form and not original-image pixel
coordinates.

5. How the three modules connect
AMG-LoRA adapts the K/V projections and uses the other modality's attention relations to
guide information retrieval. HMoE receives tokens updated by attention or the MLP,
aggregates information from both modalities into experts, and returns a fusion update
according to each token's weights. The prediction head receives the final search features,
produces center, size and offset maps, and decodes them into a bounding box.
AMG-LoRA and HMoE operate within Transformer blocks during feature processing. The
prediction head follows the encoder. HMoE still outputs token features, while the prediction
head converts those features into the target position and size used for tracking.
