English: This document follows the current project source code. It explains the mathematics of project-defined modules and computation flows, while briefly describing the roles of basic PyTorch and timm operations. All hand-calculated values are illustrative examples, not predictions from an actual checkpoint or evaluation results from the paper. Equations use row vectors multiplied by weight matrices. 一、共同的数据背景与符号
1. Shared data setup and notation

中文：以一个 RGB-D 跟踪样本为例，R 表示 RGB，X 表示深度模态。RGB-T 和 RGB-E 的处理方式相同，只需把 X 换成热红外或事件模态。一个样本同时包含模板区域和搜索区域。默认模板为 128×128，搜索区域为 256×256，patch 大小为 16×16。因此每个模态包含 64 个模板 token 和 256 个搜索 token，每个 token 有 768 个特征值。
English: Consider one RGB-D tracking sample, with R denoting RGB and X denoting depth. RGB-T and RGB-E follow the same structure, with thermal or event data as X. Each sample contains a template region and a search region. The default template is 128×128, the search region is 256×256, and each patch is 16×16. Each modality therefore contains 64 template tokens and 256 search tokens, with 768 features per token.

每个模态 / Each modality:
    [64 template tokens; 256 search tokens] = 320 tokens
    Shape = [B, 320, 768]
    B = 1 in this example

中文：B 是批大小，N 是当前模块输入的 token 数，D 是每个 token 的特征维度。H_R 和 H_X 表示经过 LayerNorm 的两路特征矩阵，并不是图像高度。h_i 表示第 i 个 token 的行向量。注意力头数用 n_head 表示，默认是 12；每头维度 d_head = 768/12 = 64。HMoE 中的 S=2 表示通道分组数，同时对应每个专家的槽位数，与注意力头数不同。
English: B is the batch size, N is the number of tokens entering the current module, and D is the feature dimension per token. H_R and H_X denote the feature matrices after LayerNorm, not image height. h_i denotes the row vector of token i. The attention head count is n_head=12, giving d_head=768/12=64. In HMoE, S=2 denotes the channel split count and also the number of slots per expert. It is distinct from the attention head count.

中文：在启用这些模块的 Transformer block 中，主要顺序为：LayerNorm、AMG-LoRA 注意力、注意力残差、HMoE 融合残差、LayerNorm 与 MLP 残差、第二个 HMoE 融合残差。经过全部 blocks 后，骨干输出搜索特征，再送入预测头。
English: In a Transformer block that enables these modules, the main sequence is LayerNorm, AMG-LoRA attention, the attention residual, an HMoE fusion residual, a LayerNorm/MLP residual, and a second HMoE fusion residual. After all blocks, the backbone outputs search features for the prediction head.

二、AMG-LoRA：注意力关系引导与低秩适配
2. AMG-LoRA: attention guidance and low-rank adaptation

2.1 源码中哪些是作者定义的？
2.1 Which parts are defined in the project?

中文：CEBlock_AP.cal_qkv、CEBlock_AP.amglora_attn 和 MergedLinear 都是项目源码中定义的函数或类，不是 PyTorch 自带的同名接口。它们内部使用 nn.Linear、LayerNorm、softmax、矩阵乘法、reshape 和 transpose 等库操作。LayerNorm 用于规范化单个 token 的特征，reshape/transpose 负责整理维度，softmax 把分数转换成权重。
English: CEBlock_AP.cal_qkv, CEBlock_AP.amglora_attn and MergedLinear are functions or classes defined in the project, not built-in PyTorch interfaces with those names. They use library operations such as nn.Linear, LayerNorm, softmax, matrix multiplication, reshape and transpose. LayerNorm normalizes each token's features, reshape/transpose organize dimensions, and softmax converts scores into weights.

2.2 第一步：由 token 计算 Q、K、V
2.2 Step 1: compute Q, K and V from tokens

中文：令输入特征经过 LayerNorm 后得到 H。Q 表示当前位置用于查询的特征，K 表示其他位置供匹配的特征，V 表示最终要取回并混合的信息。当前增强层只对 K 和 V 添加 LoRA，Q 不添加 LoRA。
English: Let H be the features after LayerNorm. Q provides query features for the current position, K provides features for matching other positions, and V carries the information to retrieve and mix. In the enhanced layers, LoRA modifies K and V only. Q has no LoRA update.

    Q = H W_Q + b_Q
    K = H W_K + b_K + H A_K B_K
    V = H W_V + b_V + H A_V B_V

    H: [B, 320, 768]
    A_K, A_V: [768, 8]
    B_K, B_V: [8, 768]

中文：A 先把 768 维映射到 8 维，B 再映射回 768 维，因此 A B 构成一个秩至多为 8 的更新矩阵。单个 K 或 V 的低秩矩阵共有 768×8+8×768=12,288 个参数。这里是在原投影上加一个可训练修正。源码将 LoRA 的 B 矩阵初始化为零，所以初始修正为零；虽然定义了 alpha/r，当前实际计算中对应乘法被注释掉，不能额外套用这个缩放。
English: A maps 768 features down to 8, and B maps them back to 768. Their product A B is an update matrix of rank at most 8. The low-rank matrices for either K or V contain 768×8+8×768=12,288 parameters. This adds a trainable correction to the original projection. The code initializes the LoRA B matrix to zero, so the initial correction is zero. Although alpha/r is defined, its multiplication is commented out in the current computation and must not be inserted into the equations.

中文：代码先一次性生成 [B,320,2304]，再拆成 Q、K、V 和 12 个头。最终每个 Q/K/V 的形状为 [B,12,320,64]。同一层的两种模态使用同一套投影参数，但输入不同，因此得到的 Q/K/V 不同。
English: The code first produces [B,320,2304], then separates Q, K and V and divides them into 12 heads. Each resulting tensor has shape [B,12,320,64]. Both modalities use the same projection parameters within a layer, but their different inputs produce different Q/K/V tensors.

2.3 第二步：分别计算两种模态的注意力分数
2.3 Step 2: compute attention scores for each modality

    S_R = Q_R K_R^T / sqrt(d_head)
    S_X = Q_X K_X^T / sqrt(d_head)
    d_head = 64, so sqrt(d_head) = 8
    S_R, S_X: [B, 12, 320, 320]

中文：第 i 行、第 j 列表示“第 i 个 token 对第 j 个 token 的匹配分数”。这些还是 softmax 之前的 logits，不是概率。cal_qkv 返回的是这个分数矩阵和 V，并不是直接把 Q、K、V 三个张量返回。
English: Entry (i,j) is the matching score between query token i and key token j. These are logits before softmax, not probabilities. Despite its name, cal_qkv returns this score matrix and V, rather than returning Q, K and V separately.

2.4 第三步：用另一模态的关系修正本模态的关系
2.4 Step 3: use the other modality to guide attention relations

    S_R_new = S_R + alpha (S_X - S_R)
    S_X_new = S_X + beta  (S_R - S_X)

    alpha = self.dte2r_scaling
    beta  = self.r2dte_scaling

中文：alpha 表示 X 引导 RGB 的强度，beta 表示 RGB 引导 X 的强度。它们是每个增强层中可训练的标量，初始化为 1，源码没有用 sigmoid 限制其范围。只有当系数在 [0,1] 内时，才能解释为两种分数的凸组合。两条更新都使用原始 S_R 和 S_X，不会把第一条已经修改的分数再送给第二条。
English: alpha controls guidance from X to RGB, while beta controls guidance from RGB to X. They are trainable scalars in each enhanced layer, initialized to 1, with no sigmoid constraint. The update is a convex combination only when the coefficient lies in [0,1]. Both directions use the original S_R and S_X. The second update does not use the already modified score matrix from the first update.

中文：这里交换的是“位置之间的关系”。RGB 分支仍使用自己的 V_R，X 分支仍使用自己的 V_X。因此其计算不是直接用 Q_R K_X^T 做跨模态注意力。
English: The guidance exchanges relations between positions. The RGB branch still uses its own V_R, and the X branch still uses its own V_X. It does not directly compute cross-modal attention as Q_R K_X^T.

2.5 第四步：取回信息并加残差
2.5 Step 4: retrieve information and add the residual

    P_R = softmax(S_R_new, along key positions)
    P_X = softmax(S_X_new, along key positions)
    O_R = ConcatHeads(P_R V_R) W_O + b_O
    O_X = ConcatHeads(P_X V_X) W_O + b_O

    X_R_after = X_R_before + O_R
    X_X_after = X_X_before + O_X

中文：softmax 后每一行的权重和为 1；训练时后续 dropout 可能改变这个和，推理时 dropout 关闭。P V 表示根据权重取所有 token 的 V 并求和，合并多头后回到 [B,320,768]，再经过输出投影。残差加回的是 LayerNorm 之前的原输入，而不是归一化后的 H。代码中的 xrgb_attn 和 xdte_attn 是特征更新量，不是 320×320 的注意力图。
English: Each softmax row sums to 1. Subsequent dropout during training can change that sum, while dropout is disabled during inference. P V forms weighted sums of token values. Concatenating the heads restores [B,320,768], followed by an output projection. The residual adds the original input from before LayerNorm, not the normalized H. The variables xrgb_attn and xdte_attn contain feature updates, not 320×320 attention maps.

2.6 一个可手算的 AMG-LoRA 例子
2.6 A hand-calculable AMG-LoRA example

中文：为了便于计算，将模型缩小为两个 token、每个 token 两维、一个注意力头、LoRA 秩为 1。以下 H 已经是 LayerNorm 后的特征。省略偏置和 dropout，基础投影以及输出投影均设为单位矩阵。
English: For a tractable example, use two tokens, two features per token, one attention head and LoRA rank 1. H below already denotes the features after LayerNorm. Omit biases and dropout, and set the base projections and output projection to identity matrices.

    H_R = [[1, 0],          H_X = [[1, 0],
           [0, 1]]                 [1, 1]]

    A_K = [[1], [0]], B_K = [[1, 0]]
    A_V = [[0], [1]], B_V = [[0, 1]]

    W_K + A_K B_K = [[2, 0], [0, 1]]
    W_V + A_V B_V = [[1, 0], [0, 2]]

    Q_R = [[1,0], [0,1]]
    K_R = [[2,0], [0,1]]
    V_R = [[1,0], [0,2]]

    Q_X = [[1,0], [1,1]]
    K_X = [[2,0], [2,1]]
    V_X = [[1,0], [1,2]]

    S_R = Q_R K_R^T / sqrt(2)
        ≈ [[1.4142, 0.0000],
           [0.0000, 0.7071]]

    S_X = Q_X K_X^T / sqrt(2)
        ≈ [[1.4142, 1.4142],
           [1.4142, 2.1213]]

中文：设 alpha=0.75。RGB 第一个 token 的分数行变为 [1.4142,1.0607]，softmax 后约为 [0.5875,0.4125]。如果没有跨模态引导，原来的 [1.4142,0] 会产生约 [0.8044,0.1956] 的权重。可以看到，X 的关系让 RGB 第一个 token 更关注第二个 token。
English: Set alpha=0.75. The first RGB token's score row becomes [1.4142,1.0607], producing approximately [0.5875,0.4125] after softmax. Without cross-modal guidance, the original row [1.4142,0] would produce approximately [0.8044,0.1956]. Relations from X therefore make the first RGB token pay more attention to the second token.

    O_R_first = 0.5875 × [1,0] + 0.4125 × [0,2]
              ≈ [0.5875, 0.8250]

中文：反方向设 beta=0.5。X 第一个 token 的分数行变为 [1.4142,0.7071]，softmax 后约为 [0.6698,0.3302]。用这个权重乘 X 自己的 V，得到 [1,0.6605] 左右。两个方向都借鉴对方的关系，但提取的仍是各自模态的信息。
English: In the opposite direction, set beta=0.5. The first X token's score row becomes [1.4142,0.7071], giving approximately [0.6698,0.3302] after softmax. Applying these weights to X's own V gives approximately [1,0.6605]. Both directions use the other modality's relations while retrieving information from their own modality.

    O_X_first = 0.6698 × [1,0] + 0.3302 × [1,2]
              ≈ [1.0000, 0.6605]

中文：最后，如果 RGB 第一个 token 在 LayerNorm 前的原输入记为 u_R，则输出为 u_R+[0.5875,0.8250]。这里用符号表示原输入，避免把演示用的 H 数值误认为未经归一化的原始特征。
English: Finally, if u_R denotes the first RGB token before LayerNorm, its output is u_R+[0.5875,0.8250]. Keeping the original input symbolic avoids confusing the illustrative normalized H with the input before normalization.

三、HMoE：先汇聚到专家，再分配回 token
3. HMoE: aggregate into experts, then distribute back to tokens

3.1 来源与功能
3.1 Implementation and purpose

中文：HMoE、LoRP 和 MultiExpertLinear 都是项目源码中的自定义类。HMoE 接收两种模态的 token，用可学习的路由权重将信息汇聚给多个专家，再把专家输出分配给每个 token。内部的 LayerNorm、softmax、矩阵乘法和 reshape 是基础库操作。
English: HMoE, LoRP and MultiExpertLinear are custom classes in the project. HMoE receives tokens from both modalities, uses learned routing weights to aggregate information into multiple experts, and distributes the expert outputs back to each token. LayerNorm, softmax, matrix multiplication and reshape are underlying library operations.

3.2 第一步：Divide & Concat
3.2 Step 1: Divide & Concat

中文：先把每个模态的 320 个 token 分成模板和搜索两段。两种模态的模板相拼，两种模态的搜索相拼。这里沿 token 维拼接，不是把两个 768 维向量拼成 1536 维。
English: First split each modality's 320 tokens into template and search segments. Concatenate the two modalities' template segments together, and concatenate their search segments together. Concatenation is along the token dimension, not along the feature dimension to create 1536-dimensional vectors.

    Z_mix = ConcatTokens(Z_R, Z_X): [B, 128, 768]
    S_mix = ConcatTokens(S_R_features, S_X_features): [B, 512, 768]

中文：模板与搜索分别调用同一个 HMoE，因此共享该模块的参数，但不在同一次 HMoE 路由中混在一起。注意力后的 HMoE 有 4 个专家，MLP 后的 HMoE 有 8 个专家，两者是独立模块。下面以注意力后的搜索融合为例，取 N=512、D=768、E=4、S=2、低秩 r=4。
English: Template and search tokens call the same HMoE module separately, sharing its parameters without mixing in a single routing operation. The HMoE after attention has 4 experts, while the HMoE after the MLP has 8 experts. They are independent modules. The following example uses search fusion after attention, with N=512, D=768, E=4, S=2 and low rank r=4.

3.3 第二步：低秩投影与通道拆分
3.3 Step 2: low-rank projection and channel splitting

    Z = LoRP_1(LayerNorm(X_mix))
    LoRP(u) = (u A + a) B + b     [inference, default activation]
    U = reshape(Z, [B, N×S, D/S])

    [B,512,768] → [B,512,768] → [B,1024,384]

中文：LoRP 默认执行 768→4→768 的带偏置映射，默认没有 GELU，训练时包含 dropout。它是一个独立的低秩投影，不是把低秩更新加到另一个冻结大矩阵上的 LoRA。随后将每个 768 维 token 按通道拆成两个 384 维子 token。拆分顺序是 token0 的两份、token1 的两份，依次排列；这一步没有重新切割图像。
English: LoRP performs a biased 768→4→768 mapping, with no GELU by default and with dropout during training. It is an independent low-rank projection, rather than a LoRA update added to another frozen full-sized matrix. Each 768-dimensional token is then split into two 384-dimensional subtokens along its channels. The order is the two parts of token 0, followed by the two parts of token 1, and so on. This operation does not cut the image into new patches.

3.4 第三步：计算路由分数和 Dispatch
3.4 Step 3: compute routing scores and Dispatch

    Phi = gate_thi: [D/S, E×S] = [384,8]
    L = U Phi: [B,1024,8]

    Dispatch[i,j] = exp(L[i,j]/T_D) / sum_k exp(L[k,j]/T_D)

中文：Phi 的每一列对应一个专家槽位。4 个专家、每个专家 2 个槽位，总共 8 个槽位。L[i,j] 表示第 i 个输入子 token 对第 j 个槽位的路由分数。Dispatch 对所有输入子 token 做归一化，因此每一列之和为 1，表示一个槽位如何从全部输入收集信息。
English: Each column of Phi corresponds to an expert slot. With 4 experts and 2 slots per expert, there are 8 slots. L[i,j] is the routing score from input subtoken i to slot j. Dispatch normalizes across input subtokens, so each column sums to 1 and determines how one slot collects information from all inputs.

    G = Dispatch^T U
    [B,8,1024] @ [B,1024,384] = [B,8,384]
    reshape G → [B,4,2,384]

中文：每个槽位得到一个 384 维加权和，其中已经可能包含 RGB、X 以及不同空间位置的信息。这里所有专家都参与运算，不是仅选择 top-k 专家的稀疏路由。
English: Each slot receives a 384-dimensional weighted sum that can contain information from RGB, X and different spatial locations. All experts participate. This is not sparse routing that selects only the top-k experts.

3.5 第四步：专家计算和第二次低秩投影
3.5 Step 4: expert computation and the second low-rank projection

    Expert_e(g) = (g A_e + a_e) B_e + b_e
    A_e: [384,4], B_e: [4,384]
    F_e = LoRP_2(ConcatChannels(Expert_e(G_e,1), Expert_e(G_e,2)))

    [B,4,2,384] → [B,4,768] → [B,4,768]

中文：不同专家使用不同参数，但同一个专家的两个槽位共享该专家的参数。每个槽位经过 384→4→384 的变换后，将同一专家的两个结果拼回 768 维，再经过共享的 linear2，即 768→4→768 的 LoRP。不能漏掉源码中的这次 linear2。
English: Different experts use different parameters, while the two slots within one expert share that expert's parameters. After each slot undergoes a 384→4→384 transform, the two outputs from the same expert are concatenated back to 768 features. The shared linear2 then applies another 768→4→768 LoRP. This additional linear2 operation is part of the implementation and must be included.

3.6 第五步：Combine 与 token 输出
3.6 Step 5: Combine and token outputs

中文：Combine 使用原始路由分数 L 的另一条计算分支。把 L 看成 [B,N,S,E,S]，将一个 token 的两个通道分组和一个专家的两个槽位所对应的分数全部相加，得到 [B,N,E]。随后沿专家维做 softmax。
English: Combine is another computation branch based on the original routing scores L. View L as [B,N,S,E,S]. Sum the scores over the two channel groups of each token and the two slots of each expert to obtain [B,N,E], then apply softmax across experts.

    M[n,e] = sum_a sum_b L[n×S+a, e×S+b]
    Combine[n,e] = softmax_e(M[n,e]/T_C)
    Y[n] = sum_e Combine[n,e] F_e

    [B,512,4] @ [B,4,768] = [B,512,768]

中文：Dispatch 回答“每个专家槽位从哪里收集信息”，Combine 回答“每个 token 从哪些专家取回多少信息”。Combine 不是对 Dispatch 再做一次 softmax。T_D 和 T_C 是可学习温度，初始化为 1，当前代码没有对其施加正值约束。
English: Dispatch determines where each expert slot collects information. Combine determines how much information each token retrieves from each expert. Combine is not a second softmax applied to Dispatch. T_D and T_C are learnable temperatures initialized to 1, with no positivity constraint in the current code.

中文：最后把输出重新拆成 RGB 和 X，分别取回模板与搜索片段，恢复每个模态的 [B,320,768] 形状，再加到对应原特征上。这一残差在 CEBlock_AP 中完成，而不是 HMoE.forward 内部完成。
English: Finally, split the outputs back into RGB and X, reunite each modality's template and search segments to restore [B,320,768], and add them to the corresponding input features. CEBlock_AP performs this residual addition, not HMoE.forward itself.

3.7 一个可手算的 HMoE 例子
3.7 A hand-calculable HMoE example

中文：为了演示，设只有两个 token：一个 RGB token 和一个 X token。每个 token 为 4 维，专家数 E=2，每专家槽位数 S=2，低秩 r=1。这里是在缩小后的数学模型中演示同一计算规则；当前源码的 LoRP 默认输入、输出维度是 768，不能只改 HMoE 的 dim 就直接运行这个四维模型。省略 dropout，令两个温度均为 1。
English: For illustration, use just two tokens: one RGB token and one X token. Each token has 4 features, with E=2 experts, S=2 slots per expert and rank r=1. This is a smaller mathematical model following the same computation rules. The current LoRP implementation defaults to 768 input and output features, so changing only HMoE's dim would not directly run this four-dimensional model. Omit dropout and set both temperatures to 1.

中文：假设 LayerNorm 和第一个 LoRP 之后得到下面两个 token。例子从这一中间结果开始，不把它当作未经处理的原输入。
English: Assume LayerNorm and the first LoRP produce the following tokens. The example starts at this intermediate result, which is distinct from the original input.

    Z_R = [1,0,0,1]
    Z_X = [1,0,0,0]

    U = [[1,0],     RGB first channel group
         [0,1],     RGB second channel group
         [1,0],     X first channel group
         [0,0]]     X second channel group

中文：设 gate_thi 为下面的矩阵，其中前两列属于专家 1，后两列属于专家 2。ln(2) 是 2 的自然对数，其指数恰好为 2，因此方便手算 softmax。
English: Set gate_thi to the matrix below. Its first two columns belong to expert 1, and its last two columns belong to expert 2. ln(2) is the natural logarithm of 2. Its exponential is exactly 2, making softmax easy to calculate.

    Phi = [[ln(2), 0,     0, 0],
           [0,     ln(2), 0, 0]]

    L = U Phi
      = [[ln(2), 0,     0, 0],
         [0,     ln(2), 0, 0],
         [ln(2), 0,     0, 0],
         [0,     0,     0, 0]]

中文：沿输入子 token 方向做 softmax，得到四个槽位分别使用的收集权重。下面每一行列出一个槽位对应的整列权重。
English: Apply softmax across input subtokens to obtain the collection weights for each of the four slots. Each line below lists one complete column of Dispatch.

    Expert 1, slot 1: [2,1,2,1]/6
    Expert 1, slot 2: [1,2,1,1]/5
    Expert 2, slot 1: [1,1,1,1]/4
    Expert 2, slot 2: [1,1,1,1]/4

    G_1,1 = [2/3, 1/6]
    G_1,2 = [2/5, 2/5]
    G_2,1 = [1/2, 1/4]
    G_2,2 = [1/2, 1/4]

中文：例如，专家 1 的第一个槽位等于 (2/6)[1,0]+(1/6)[0,1]+(2/6)[1,0]+(1/6)[0,0]，结果为 [2/3,1/6]。此时一个槽位已经混合了两个模态的信息。
English: For example, the first slot of expert 1 equals (2/6)[1,0]+(1/6)[0,1]+(2/6)[1,0]+(1/6)[0,0], giving [2/3,1/6]. This slot already combines information from both modalities.

中文：为了演示低秩专家计算，设专家 1 把 [x,y] 映射为 [x,2x]，专家 2 映射为 [2y,y]。它们都能写成秩为 1 的 A_e B_e 映射，偏置设为零。同一专家的两个槽位分别计算后再拼接。
English: To illustrate low-rank expert computation, let expert 1 map [x,y] to [x,2x] and expert 2 map [x,y] to [2y,y]. Both can be expressed as rank-1 A_e B_e mappings with zero bias. Process each expert's two slots separately, then concatenate their outputs.

    Expert 1:
      [2/3,1/6] → [2/3,4/3]
      [2/5,2/5] → [2/5,4/5]
      Concatenated = [2/3,4/3,2/5,4/5]

    Expert 2:
      [1/2,1/4] → [1/2,1/4]
      [1/2,1/4] → [1/2,1/4]
      Concatenated = [1/2,1/4,1/2,1/4]

中文：接着必须经过源码中的 linear2。设这个共享的秩 1 投影先将第 1、3 个分量相加得到 t，再输出 [t,0,t,0]。
English: Next apply linear2, as required by the source code. Let this shared rank-1 projection add the first and third components to obtain t, then output [t,0,t,0].

    F_1 = [16/15,0,16/15,0]
    F_2 = [1,0,1,0]

中文：再看 Combine。RGB token 对专家 1 的四个相关分数之和为 2ln(2)=ln(4)，对专家 2 为 0。因此它读取两个专家的权重是 [4/5,1/5]。X token 对两个专家的聚合分数是 [ln(2),0]，权重为 [2/3,1/3]。
English: Now compute Combine. For the RGB token, the four scores associated with expert 1 sum to 2ln(2)=ln(4), while the sum for expert 2 is 0. Its expert weights are therefore [4/5,1/5]. For the X token, the aggregated expert scores are [ln(2),0], yielding weights [2/3,1/3].

    Y_R = (4/5)F_1 + (1/5)F_2
        = [79/75,0,79/75,0]
        ≈ [1.0533,0,1.0533,0]

    Y_X = (2/3)F_1 + (1/3)F_2
        = [47/45,0,47/45,0]
        ≈ [1.0444,0,1.0444,0]

中文：这就是 HMoE 返回的两个 token 更新量。如果调用 HMoE 前的原始 RGB token 记为 u_R，则调用方得到 u_R+Y_R；X 同理。不同 token 的 Combine 权重不同，所以即使读取同一组专家，输出也可以不同。
English: These are the two token updates returned by HMoE. If u_R denotes the RGB token before the HMoE call, the caller obtains u_R+Y_R, and similarly for X. Different tokens have different Combine weights, so they can produce different outputs while reading the same set of experts.

四、预测头：把搜索特征变成目标框
4. Prediction head: convert search features into a bounding box

4.1 来源与输入
4.1 Implementation and input

中文：CenterPredictor、get_score_map、cal_bbox 和模型的 forward_head 是项目中定义的结构或函数。内部使用 PyTorch 的 Conv2d、BatchNorm2d、ReLU、sigmoid、max 和 gather。卷积提取局部特征，BatchNorm 规范化中间激活，ReLU 提供非线性，gather 按选定索引取值。下面重点解释三个输出分支如何一起完成框预测。
English: CenterPredictor, get_score_map, cal_bbox and the model's forward_head are structures or functions defined in the project. They use PyTorch Conv2d, BatchNorm2d, ReLU, sigmoid, max and gather. Convolutions extract local features, BatchNorm normalizes intermediate activations, ReLU supplies nonlinearity, and gather retrieves values at selected indices. The explanation below focuses on how the three output branches jointly predict a box.

中文：全部 Transformer blocks 处理结束后，两路特征经过最后的归一化，并取搜索部分。RGB 和 X 的搜索特征逐位置、逐通道相加，得到 [B,256,768]。这是求和，不是通道拼接。
English: After all Transformer blocks, both streams undergo final normalization, and the search features are selected. The RGB and X search features are added element by element, producing [B,256,768]. This is addition, not channel concatenation.

    F_search = F_R_search + F_X_search
    [B,256,768] → [B,768,16,16]

中文：256 个搜索 token 对应 16×16 个空间位置，因此可以恢复成二维特征图。每个位置有 768 个通道。模板特征没有单独送进预测头，但已经在前面的注意力计算中影响了搜索特征。
English: The 256 search tokens correspond to a 16×16 spatial grid, so they can be reshaped into a two-dimensional feature map with 768 channels per location. Template features are not separately passed to the prediction head, but they have already influenced the search features through earlier attention operations.

4.2 三个独立分支
4.2 Three independent branches

中文：中心分数、尺寸和偏移三个分支具有相同的层次结构，但各用各的卷积参数。每支先经过四层 3×3 的 Conv-BN-ReLU，通道数为 768→256→128→64→32，空间大小保持 16×16。最后一层 1×1 卷积输出所需的通道数。
English: The center-score, size and offset branches have the same layer structure but use separate convolution parameters. Each branch applies four 3×3 Conv-BN-ReLU layers with channels 768→256→128→64→32, keeping the spatial grid at 16×16. A final 1×1 convolution produces the required output channels.

    Center score / 中心分数:
      score_map: [B,1,16,16]
      Meaning: target-center score at each grid position
      含义：每个网格位置作为目标中心的分数

    Size / 尺寸:
      size_map: [B,2,16,16]
      Meaning: normalized width and height at each position
      含义：每个位置预测的归一化宽度和高度

    Offset / 偏移:
      offset_map: [B,2,16,16]
      Meaning: x and y corrections relative to each grid coordinate
      含义：相对网格坐标的 x、y 方向修正量

中文：中心分数和尺寸经过 sigmoid，并限制在 [0.0001,0.9999]。偏移不经过 sigmoid，可以取任意实数。中心分数是在每个位置独立计算的，并不是对 256 个位置做一次 softmax，因此整张中心分数图的分数和不要求为 1。
English: Center scores and sizes pass through sigmoid and are clamped to [0.0001,0.9999]. Offsets have no sigmoid and can take arbitrary real values. Center scores are computed independently at each location, rather than using a single softmax over all 256 locations, so the entire score map need not sum to 1.

4.3 选择位置，并在同一位置取出尺寸与偏移
4.3 Select a location and retrieve its size and offset

    idx = argmax(flatten(score_map))
    row = idx // 16
    col = idx % 16
    [w,h]   = size_map at idx
    [dx,dy] = offset_map at idx

中文：先在中心分数图找到最大分数位置，再从尺寸图和偏移图的同一个位置取值。不能让三个分支分别选各自的最大值，否则中心、宽高和偏移可能来自三个不同位置。
English: First find the location with the highest center score, then retrieve size and offset from that same location. The three branches must not independently select their own maxima, because that could combine a center, size and offset from different positions.

4.4 解码归一化目标框
4.4 Decode the normalized bounding box

    cx = (col + dx) / 16
    cy = (row + dy) / 16
    box = [cx, cy, w, h]

中文：cx、cy 是相对搜索图的归一化中心坐标。w、h 已经是相对搜索图的归一化宽高，因此不要再除以 16。此时输出是中心形式 cxcywh，不是左上角形式 xywh，也不是原图像素坐标。
English: cx and cy are center coordinates normalized relative to the search image. w and h are already normalized to the search image, so they must not be divided by 16 again. The output is in center-based cxcywh form, not top-left xywh form and not original-image pixel coordinates.

4.5 一个完整的数值例子
4.5 A complete numerical example

中文：假设选中第 7 行、第 9 列，行列均从 0 开始。该位置的中心分数为 0.92，偏移为 [0.25,0.5]，尺寸为 [0.25,0.5]。这些数值是假设的预测输出，用来演示解码。
English: Suppose the selected position is row 7, column 9, using zero-based indexing. Its center score is 0.92, offset is [0.25,0.5], and size is [0.25,0.5]. These are hypothetical predictions used to illustrate decoding.

    idx = 7×16 + 9 = 121
    cx = (9+0.25)/16 = 0.578125
    cy = (7+0.5)/16 = 0.46875
    w = 0.25
    h = 0.5

    Normalized box / 归一化目标框:
      [0.578125, 0.46875, 0.25, 0.5]

中文：将这个框换算到网络输入的 256×256 搜索图中，所有分量乘以 256，得到中心 [148,120]、宽高 [64,128]。再减去半个宽高，得到左上角 [116,56]。
English: To express this box in the 256×256 search image supplied to the network, multiply all components by 256. The center becomes [148,120], and the size becomes [64,128]. Subtract half the width and height to obtain the top-left coordinate [116,56].

    Search-image cxcywh = [148,120,64,128]
    Search-image xywh   = [116,56,64,128]

中文：预测头使用的是搜索序列中的第 121 个索引。如果回看之前包含 64 个模板 token 的完整序列，在未裁剪且顺序保持的情况下，它对应的完整序列索引为 64+121=185。
English: The prediction head uses index 121 within the search sequence. In the earlier full sequence containing 64 template tokens, it corresponds to index 64+121=185, provided tokens have not been pruned and their order is preserved.

4.6 Tracker 后处理与原图坐标
4.6 Tracker post-processing and original-image coordinates

中文：实际跟踪代码先将中心分数图乘以 Hann 窗，再重新调用 cal_bbox。这个窗偏好搜索区域中心附近的位置，因此最终选择的位置可能不同于直接对原始 score_map 取最大值的结果。上述例子可以理解为加窗后仍选中第 7 行、第 9 列。
English: The tracker multiplies the center-score map by a Hann window and then calls cal_bbox again. This window favors positions near the search-region center, so the final selected location can differ from the raw score-map maximum. The example above can be interpreted as a case where row 7, column 9 remains selected after windowing.

    response = HannWindow × score_map
    box = cal_bbox(response, size_map, offset_map)

中文：设原图中裁剪的搜索区域边长为 512 像素，缩放到 256 像素送入模型，因此 resize_factor=0.5。归一化框乘 search_size/resize_factor=512，得到相对原图裁剪区域的像素坐标。
English: Suppose the search crop spans 512 pixels in the original image and is resized to 256 pixels for the model, giving resize_factor=0.5. Multiply the normalized box by search_size/resize_factor=512 to obtain pixel coordinates relative to the crop in the original image.

    Crop-relative cxcywh:
      [0.578125,0.46875,0.25,0.5] × 512
      = [296,240,128,256]

中文：若该裁剪区域在原图中的坐标原点为 [100,200]，则目标中心为 [296+100,240+200]=[396,440]。再转成左上角形式，得到 [332,312,128,256]。在源码的 map_box_back 中，裁剪原点由上一帧目标中心减去裁剪边长的一半计算；最后还会将框限制在图像边界内。
English: If the crop origin in the original image is [100,200], the target center is [296+100,240+200]=[396,440]. Converting to top-left form gives [332,312,128,256]. In map_box_back, the crop origin is computed from the previous frame's target center minus half the crop side length. The final box is also clipped to the image boundaries.

    Original-image center = [396,440]
    Original-image size   = [128,256]
    Original-image xywh   = [396-64,440-128,128,256]
                          = [332,312,128,256]

五、三个模块如何衔接
5. How the three modules connect

中文：AMG-LoRA 在注意力计算中调整 K/V 投影，并利用另一模态的注意力关系修正本模态的取信息方式。HMoE 接收注意力或 MLP 更新后的 token，将两种模态的信息汇聚到专家，再按每个 token 的权重返回融合增量。预测头接收最终搜索特征，生成中心、尺寸和偏移图，再将它们解码成目标框。
English: AMG-LoRA adapts the K/V projections and uses the other modality's attention relations to guide information retrieval. HMoE receives tokens updated by attention or the MLP, aggregates information from both modalities into experts, and returns a fusion update according to each token's weights. The prediction head receives the final search features, produces center, size and offset maps, and decodes them into a bounding box.

中文：AMG-LoRA 和 HMoE 位于 Transformer blocks 的特征处理过程中；预测头位于编码器之后。HMoE 的输出仍然是 token 特征，预测头才将这些特征转换成可用于跟踪的目标位置与大小。
English: AMG-LoRA and HMoE operate within Transformer blocks during feature processing. The prediction head follows the encoder. HMoE still outputs token features, while the prediction head converts those features into the target position and size used for tracking.
